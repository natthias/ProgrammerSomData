The [] at the beginning of each line is the current environment ρ.
The proceeding {} contains the pending instruction.
All the instructions then work on ρ and push/pop values from it.

8.4
The reason prog1 is faster is because it includes less instructions.
It is able to do this, as it avoids using an explicit variable and instead manipulates the stack directly.
This allows the program to not have to deal with LDI/STI, as it never has to perform a lookup on the stack.

Loops and conditions usually interact through GOTO (70) and comparisons, such as IFNZRO (71) or IFZERO (72).
The conditions are inverted from the code and if the condition in the bytecode is not true, a GOTO is performed and it moves back to the start of the loop.
This is done continuously, some might even say "in a loop", until the condition is no longer met, and program execution continues outside of the loop.

For example, the part `10 40 0 100 14 72 64` adds the 10th local variable to the stack, adds 100 to the stack, performs modulo on these two numbers,
and if the result is not 0, it jumps to instruction number 64.
This extract of the code translates to `y % 100 != 0`.
